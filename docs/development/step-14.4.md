# Step 14.4 — メニューとオンラインダイアログの分離

**実施日:** 2026-10-21
**対象:** 右上メニュー、ルーム作成・参加フォーム、既存オンライン待機画面
**状態:** 実装・ローカル検証済み。GitHub Actionsとmain反映の結果は[検証記録](../verification/step14.4/README.md)を参照。iPhone Safari実機は未確認。

## 変更内容

- 右上メニューを「オフラインで新規対局」「新しくルームを作る」「ルームに参加する」の順に変更しました。ルーム参加中は既存の「ルーム操作」も表示します。メニューの外側タップ、Escape、矢印キー、Home/End、フォーカス制御は維持しています。
- 作成フォームと参加フォームを独立したダイアログにしました。作成画面は表示名と作成ボタンだけ、参加画面は表示名・ルームコードと参加ボタンだけを表示します。必要な入力条件が満たされるまで送信ボタンを無効にします。
- 表示名は別々の入力欄から共通のページ内状態へ同期します。入力中は両欄に反映し、成功したルームの参加セッションと表示名は従来の`sessionStorage`へ保存します。`localStorage`や独立した永続保存先は追加していません。
- オンライン参加中は作成・参加画面を開けますが、既存セッションを置き換えないよう送信を無効にし、「ルーム操作」から退出した後に行うよう案内します。オフライン新規対局は既存の確認・開始処理を使います。
- 作成・参加成功後はフォームを閉じ、ルームコード共有、参加者、Ready、CPU席、ホスト操作を含む従来のオンライン待機画面を開きます。オンライン対局とWorkerの通信・進行処理は変更していません。
- フォームと待機画面は既存配色に合わせ、縦積み入力、44px以上の操作領域、動的ビューポート高、内部スクロール、閉じるボタンを設定しました。

## 検証

実行コマンドとGitHub Actions結果は[Step 14.4検証記録](../verification/step14.4/README.md)、工程別の実測・概算時間は[処理時間記録](../verification/codex-performance/step14-4-menu-dialog-separation.md)を参照してください。

最初のBrowser UI runで、作成ダイアログを閉じた直後のフォーカス復帰検査が失敗しました。閉じる処理が`close`イベントの後続処理だけに依存していたため、メニューボタンへのフォーカス復帰を閉じる処理の中でも同期的に実行するよう修正しました。検査の期待値は変えていません。
