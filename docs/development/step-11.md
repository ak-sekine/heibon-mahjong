### 固定ルールと符計算

四人打ち日本式リーチ麻雀、現在の全和了手牌は門前、東場固定。自風は`PlayerState.wind`、親は`GameState.dealerId`で判断します。鳴き・喰いタン処理はありません。

`src/analysis/fu.ts`のDOM非依存純粋関数`calculateFu(candidate, context)`は既存`YakuCandidate`の分解・和了牌割り当て・待ち・役を使います。入力候補や配列を変更せず、和了形・成立役の再判定や変更は行いません。

| 要素 | 符 |
| --- | ---: |
| 標準形の基本符 | 20 |
| 門前ロン | +10 |
| ツモ（平和以外） | +2 |
| 中張牌の明刻／暗刻 | +2／+4 |
| 么九牌・字牌の明刻／暗刻 | +4／+8 |
| 順子 | 0 |
| 数牌・役牌以外の雀頭 | 0 |
| 三元牌の雀頭 | +2 |
| 自風の雀頭 | +2 |
| 場風の雀頭 | +2 |
| 自風・場風が重なる雀頭 | +4 |
| 両面・シャンポン待ち | 0 |
| 嵌張・辺張・単騎待ち | +2 |

シャンポンロンでは`candidate.assignment.meldIndex`が示す完成刻子だけを符計算上の明刻として扱います。手牌は門前のままで門前ロン10符を維持します。シャンポンツモは完成刻子も暗刻です。東場の親の東雀頭は4符です。合計を原則10符単位で切り上げます（22→30、32→40、42→50）。

例外：平和ツモは20符固定（ツモ2符なし）、平和ロンは20＋10＝30符。七対子は和了方法によらず25符固定で、基本符・和了方法・単騎待ちの加算も30符への切り上げもしません。通常役満は符を点数に使用せず、`rawFu`・`fu`を`null`、内訳を空配列にします。国士無双に架空の符は表示しません。カン・カンの符は対象外です。

`FuResult`は`rawFu`（切り上げ前）、`fu`（最終符）、`fuMode`（`standard / pinfu-tsumo / seven-pairs / yakuman`）、`fuBreakdown`を保持します。内訳は`type`と`fu`を持つ構造化データです。刻子には牌種・面子番号・暗刻か・么九牌か、雀頭には牌種・三元牌／自風／場風の各フラグ、待ちには既存の待ち種別を記録します。固定符も専用`type`で表します。日本語ラベルと折りたたみ表示は描画層で生成し、DOMで符を再計算しません。

### 基本点・限界点・支払い

`src/analysis/score.ts`の`calculateBasePoints(han, fu, yakumanCount)`と`calculateScore(context)`は純粋関数です。通常手では役＋通常ドラ＋赤ドラの合計翻を使い、ドラは符には影響しません。通常手の翻数による上限を先に判断し、満貫未満の基本点は`符 × 2^(翻＋2)`です。

| 条件 | `scoreTier` | 基本点 |
| --- | --- | ---: |
| 1〜4翻、基本点2000未満 | normal | 符から計算 |
| 基本点2000以上、または5翻 | mangan（満貫） | 2000 |
| 6〜7翻 | haneman（跳満） | 3000 |
| 8〜10翻 | baiman（倍満） | 4000 |
| 11〜12翻 | sanbaiman（三倍満） | 6000 |
| 13翻以上 | kazoe-yakuman（数え役満） | 8000 |
| 通常役満 | yakuman | 8000 × yakumanCount |

切り上げ満貫は不採用です。基本点1920の3翻60符・4翻30符は満貫に上げません。数え役満は1倍役満相当で、通常役満と区別して保存します。13翻以上でも成立役と`yakumanCount`を変更しません。通常役満の通常ドラ・赤ドラ翻は0のままで、枚数自体は既存の意味で保持します。

- ロン：子は基本点×4、親は×6を100点単位で切り上げ、放銃者1人が全額支払い。
- 親ツモ：他3人が基本点×2をそれぞれ100点単位で切り上げ。
- 子ツモ：親は基本点×2、他の子2人は×1をそれぞれ100点単位で切り上げ。
- `totalPoints`は切り上げ後の各支払いの合計。子の20符2翻ツモは基本点320、子400＋400・親700＝1500点。合計だけを最後に切り上げません。

親の満貫ロン12000／ツモ4000オール、子の満貫ロン8000／ツモ2000・4000。親の役満ロン48000／ツモ16000オール、子の役満ロン32000／ツモ8000・16000です。

`WinDetails`に`rawFu / fu / fuMode / fuBreakdown / scoreTier / basePoints / payments / totalPoints`を追加し、継承する`TsumoResult / RonCandidate`にも保存します。`payments`は`{ playerId, points }`の配列、受取人はその結果の`winnerId`です。既存の候補・翻・ドラのフィールドの意味は維持します。`RonResult.winners`の勝者ごとに独立して計算し、ダブロン・トリプルロンでは同じ放銃者から各勝者への支払いを別々に記録します。異なる勝者の翻・符・点数を混ぜません。トリプルロン成立ルール、フリテン・一時フリテン・宣言待ち・CPU処理も維持しています。

### 最大得点候補と結果画面

共通の`evaluateWin()`で合法な各候補の役翻、ドラ、符、親子・和了方法による支払いを求めます。`selectScoredWinCandidate()`は獲得合計点数を優先し、同点なら役満数→役翻数→最終符数→候補IDの昇順で決定します。入力順に依存せず、役と符を候補間で合算しません。選択した1候補とその計算結果だけを保存します。従来の`selectWinCandidate(analysis)`と`selectTsumoCandidate`は旧優先順位のまま互換APIとして維持します。ツモ・ロン・全CPU・同時ロンで同じ点数評価を使用します。

和了結果パネルに翻、符、獲得点数、満貫以上の名称、親子・和了方法、支払者→勝者・金額を表示します。`details / summary`の「符の内訳」は通常閉じ、展開すると計算済み内訳・切り上げ前・最終符を表示します。平和ツモ・七対子の固定符も明記します。役満は符と符内訳を表示しません。複数ロンでは勝者別の14枚・役・点数・支払いを表示します。

点数情報は結果パネルだけに追加しました。卓の高さ、中央ドラ3＋2配置、河の回転・牌サイズ、手牌14枚の横1行、ロン／見逃す／打牌／ツモ操作、SafariセーフエリアCSSを維持します。長い結果と内訳は文書の縦スクロールで確認でき、支払い情報は通常のテキスト・リストとしてアクセシビリティツリーにも含まれます。
