## Step 13.1.1：供託点棒の視覚表示
> **歴史資料:** 以下は整理前READMEのStep記録です。実施当時の仕様・未実装項目・検証結果を示し、現在の仕様を表すものではありません。現在の仕様は [SPEC](../SPEC.md)、実装状況は [ROADMAP](../ROADMAP.md) を参照してください。

卓中央のドラ3＋2枠にある下段の空きセルに供託点棒を表示します。ドラ表示牌・牌山情報・4人の河の寸法を維持し、供託0ではDOMの点棒を除去して領域を非表示にします。ヘッダーの本数は補助表示として残します。供託したプレイヤーは表示しません。

`src/rendering/deposit-sticks.ts` の `getDepositDisplaySticks()` は、既存の `MatchState.depositSticks × 1000` を10,000→5,000→1,000点の順に表示用だけ両替し、種類と本数の凍結データを返します。非整数・負数・非数値・安全な整数範囲を超える金額はRangeErrorで拒否します。供託データ、精算、リーチ条件、局進行には変更を加えていません。

SVGは外部画像を使わず、牌と同じアイボリー（#fffdf7）と薄い縁・陰影を使用します。共通viewBoxは60×12、卓上は26×8pxです。1,000点は赤い大きな点1個、5,000点は赤い点3個の横列、10,000点は紺色の点6個を3列×2段に配置し、色以外でも区別できます。省スペース化した4本までを下段空きセルに縦に並べ、それ以上はセル内でスクロールし、卓の高さを増やしません。

領域を `role="img"` とし、「供託合計 6000点。5000点棒1本、1000点棒1本」のような名前で総額と内訳を一度に読み上げます。個々の点棒・SVG装飾はaria-hiddenです。`renderMatch()` の精算表示キャッシュ判定より前に描画するため、リーチ成立、自己・他家和了、流局、次局、新対局でも表示を同期します。結果ウィンドウの開閉では状態を書き換えません。

### 検証方法

- `npm test`：既存607件＋表示用21件＝628件。供託0/1/4/5/6/10/12/17/25本、金額一致、不正値、不変データ、MatchState非変更、リーチ・自己/他家回収・持越し・リセット、100,000点保存則を検証します。個別件数は `node --test --test-isolation=none tests/*.test.ts` でも確認できます。
- `npm run build`：TypeScriptとViteの本番ビルド。
- `tests/browser-deposit-sticks.mjs`：Chromiumの320×568、375×667、390×844、414×896、1280×800、375×547、390×724で0/1,000/5,000/6,000/10,000/17,000点を検証。全河18枚を表示し、重なり、卓寸法不変、手牌14枚横1行、操作欄との重なり、ボタンの可視性、横スクロール、CPU手牌・未公開王牌の非公開を確認しました。42枚の画像と `chromium-results.json` を `docs/screenshots/step13.1.1/` に保存しました。
- 実行例：別ターミナルで `npm run dev -- --host 127.0.0.1`、Playwrightを利用できる環境で `node tests/browser-deposit-sticks.mjs`。外部のPlaywrightを使う場合は `QUILL_PLAYWRIGHT=/tmp/heibon-browser/node_modules/playwright/index.mjs` を指定できます。
- `python3 tests/browser-deposit-lifecycle.py`：既存Step 13.1の実操作回帰に供託表示額の一致検証を追加。7サイズでリーチ、ツモ切り、自己和了、宣言牌CPUロン、結果/卓切替、次局、新対局を確認し、`lifecycle/` に画像・結果を保存します。
- iPhone Safari実機は未確認です。点の配置の見分けやすさ、VoiceOverの総額読み上げ、アドレスバー伸縮、セーフエリア、短画面での手牌と操作欄を実機で確認してください。
