## Step 8.1：赤ドラの翻数計算と結果表示
> **歴史資料:** 以下は整理前READMEのStep記録です。実施当時の仕様・未実装項目・検証結果を示し、現在の仕様を表すものではありません。現在の仕様は [SPEC](../SPEC.md)、実装状況は [ROADMAP](../ROADMAP.md) を参照してください。

`src/analysis/dora.ts`の`countRedDora(tiles: readonly Tile[]): number`は、`Tile.isRed`で赤5萬・赤5筒・赤5索を数える純粋関数です。各1枚につき1翻で、通常の5は0翻です。役・和了形判定には依存せず、入力配列・牌・PhysicalTile・GameStateを変更しません。完成手牌13枚＋実際のツモ牌1枚を、各宣言の評価時に一度数えます。面子分解・七対子などの候補ごとに加算せず、和了牌自身が赤5でも含めます。

赤ドラは役ではなく、成立役に付加するボーナスです。役一覧に追加せず、役なしの和了を可能にしません。Step 6・7の判定、役満数→役の翻数→候補IDの選択順、通常ツモの取得元・手番・14枚・物理ID一意性の検証を維持します。

`TsumoResult`の翻数は以下のように分けて保持します。

| フィールド | 意味 |
| --- | --- |
| `totalHan` | 従来どおり選択候補の役翻数。互換性を維持 |
| `yakuHan` | `candidate.totalHan`と同じ役翻数 |
| `redDoraCount` | 実際の完成手牌内の赤牌枚数 |
| `redDoraHan` | 通常役なら赤牌枚数と同じ翻数、役満なら0 |
| `totalHanIncludingDora` | 通常役なら`yakuHan + redDoraHan`、役満なら0 |
| `yakumanCount` | 役満数。赤ドラでは増やさない |

`YakuCandidate.totalHan`は変更しません。役満時はボーナスを上乗せせず、結果画面は役満数だけを表示して通常翻数との合計を表示しません。現在対応する国士無双には赤5を含められません。将来赤牌を含む役満に対応しても、枚数の記録だけで増額しない構造です。

入力は既存のTileモデルに従います。赤は数牌の5だけで、未知の牌面・不正な赤属性・同じ色の赤5複数枚は`RangeError`です。APIは任意の長さの牌面配列を受け付け、14枚・各牌種4枚以下・物理IDの検証は和了処理側が担当します。牌面APIはIDを持たないため、オブジェクト参照をIDとして扱いません。ゲーム層ではID重複を拒否してから牌面を渡し、不正入力時の和了宣言は拒否します。

Step 8.1時点の実装済みドラは赤ドラのみです。通常ドラと表示牌管理・UIは以下のStep 8.2で追加しました。裏ドラ・槓ドラは未実装です。役一覧・ボーナス表示領域（`win-bonuses`）・合計を分け、今後のボーナス表示を追加できる配置にしています。0枚でも必ず「赤ドラ：0枚（0翻）」と表示します。結果は既存の文書配置で自然に縦スクロールできます。

赤5萬・赤5索を含む和了結果の表示例：

