## Step 8：自分のツモ和了と対局終了
> **歴史資料:** 以下は整理前READMEのStep記録です。実施当時の仕様・未実装項目・検証結果を示し、現在の仕様を表すものではありません。現在の仕様は [SPEC](../SPEC.md)、実装状況は [ROADMAP](../ROADMAP.md) を参照してください。

`src/game/tsumo.ts`の純粋関数`canDeclareTsumo(game, playerId)`と`declareTsumo(game, playerId)`を追加しました。対象はPlayerId=0・human・自分の手番・門前のみです。`phase: awaiting-discard`で手牌13枚＋実際に生きた牌山から取得した`drawnTile`1枚があり、Step 7の`analyzeYaku()`が和了形と対応役を認める場合に宣言できます。終了済み・不正な牌数・存在しないプレイヤー等は不可で、宣言関数は`RangeError`を投げます。最終生牌を引いた直後も宣言可能です。壁の空判定は次のツモ時に行う既存仕様を維持します。

「ツモ和了」は通常は無効です。有効になったら、ボタンで明示的に和了を宣言するか、従来どおり牌を選択して「打牌する」で続行できます。自動和了はしません。選択中の牌にかかわらず和了牌は現在の`drawnTile`で、宣言後は選択を解除します。打牌するとそのツモでの和了機会は終了し、次の自分のツモで再判定します。

`PlayerState.drawnTileSource`を配牌時`deal`、生きた牌山のツモ時`live-wall`、打牌後`null`にします。親の配牌追加牌は通常ツモと区別して和了を許可しません（天和未実装）。牌山残数や河から取得元を推測しません。Step 7には手牌＋ツモ牌の牌面、`winMethod: tsumo`、実際のツモ牌種、自分の席風、東場を渡します。場風は`ROUND_WIND`の一箇所で管理します。Step 6の`analyzeWinningShapes()`はStep 7内部で再利用し、両判定エンジンは変更していません。

和了後は`GameState.phase: won`になり、`winResult: TsumoResult`に勝者、和了方法、和了牌の物理ID、Step 7の全候補分析、表示候補、通常翻数、役満数を保持します。通常翻と役満を混ぜません。手牌・drawnTile・河・生牌山・王牌はそのままで、不変な状態を返します。打牌・ツモ・二重和了・CPU自動進行は停止し、「新しい対局」で`winResult: null`に初期化します。`wall-exhausted`は別の終了状態です。

結果は「ツモ和了！」、自分の名前と席風、成立役と翻数または役満数、対応役合計、「今回対応している役の判定結果」、「点数計算は未実装です。」を表示します。表示候補は役満数優先→通常翻数の多い順→候補IDの決定的な順で選びます。符・点数がないため最高得点を意味しません。Step 7の対応役のみを扱い、未対応役（上記Step 7一覧）は表示・加算しません。

ControllerはCPU処理中の操作を遮断し、和了時・リセット時にRunnerのAbortControllerと世代番号で古い処理を無効化します。Runnerは和了状態で進行せず、待機後に最新状態を再取得します。完了通知は実行中フラグを解除した後、同じ世代に限って行い、CPU3打牌後の自分の自動ツモでボタンが直ちに有効になります。古い世代の完了通知は新対局に影響しません。

両操作ボタンは44px以上、狭い画面では操作メッセージとボタンを別行にします。Step 5の1行手牌、河の位置・回転、CPU手牌非公開、sticky操作領域、svh・セーフエリアを維持し、結果は文書内で縦スクロールできます。

テスト用の固定牌山は`tests/tsumo-fixture.ts`にあり、実際の136枚から物理牌を並べ、配牌→打牌→ツモを通じて再現します。136枚・ID重複なし・各種4枚・赤5各色1枚・王牌14枚を維持します。本番UIにテスト操作は追加しません。Chromium検証は次のようにVite開発サーバーに対して実行します（通常previewの既存検証も使用可能）。ブラウザ内で開始状態の注入だけを差し替え、実際のControllerと操作UIを使用します。

```sh
npm run dev -- --host 127.0.0.1 --port 4173
python tests/browser-check.py --tsumo-fixture
```

320×568、375×667、390×844、414×896、1280×800と各サイズの高さ120px減で、無効／有効ボタン、牌選択との独立、明示宣言、14枚維持、役・翻数表示、打牌とCPU停止、リセット、通常打牌との共存、44pxタップ領域・非重複・横スクロールなしを検証します。
