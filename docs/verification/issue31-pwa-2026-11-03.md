## 確認できた原因と範囲

- `79b939e956b82ce025e7373c5f077d68f9ebb9b4` は fetch 後の `origin/main` と一致し、PWAのソース変更はmainに入っていました。開始時の作業ツリーはcleanでしたが、作業ブランチ`work`はmainより6コミットbehindでした。調査は最新mainから開始しました。
- 指定run [41600214270](https://github.com/ak-sekine/heibon-mahjong/actions/runs/41600214270) は `push` イベント、head SHA `79b939e…` です。`verify`（回帰テスト、Worker型検査、Pages build）とChromium／WebKit Browser UIは成功しました。初回確認時の最新成功デプロイ記録はWorker／Pagesとも `fc638eaec20c3f6f121a9245c2359a37ffd76866` で、PWA実装SHAはまだ公開成功記録にありませんでした。よってbuild成功だけではPWAが公開されたとは確認できず、Worker／Pages deployと対象SHA記録の完了を別に待つ必要がありました。
- 同runは後にmatrix audit、Worker production test、Pages build／deployをすべてsuccessで完了しました。Worker／Pages双方の成功deployment SHAは `79b939e956b82ce025e7373c5f077d68f9ebb9b4` です。従って前回実装は最終的に公開されましたが、利用者コメントが投稿された時点（2026-11-03 08:02 UTC）ではBrowser UI・公開ゲートが進行中で、直前の成功公開SHAは `fc638ea…` でした。コメント時点のbuild成功と公開成功の間に遅延があった事実は確認できました。利用者報告の具体的な再現条件がないため、個別の不具合原因までは断定しません。
- 公開URLのHTTP検証は通常実行とネットワーク許可付き実行の両方で失敗しました。`ak-sekine.github.io`への接続はプロキシCONNECT HTTP 403（`curl: (56) CONNECT tunnel failed, response 403`）でした。したがって今回、公開HTML／manifest／アイコン／sw.jsの実レスポンス、MIME・cache header、実際の公開SHAは直接取得確認できていません。Actionsの成功デプロイ記録とは別の未確認事項です。
- Issue報告の具体的な失敗操作は未特定で、報告者の再現条件も得られていません。従って「利用者の失敗はこれが原因」とまでは断定できません。一方、既存Service Workerはナビゲーション取得と事前キャッシュで通常のHTTP cacheを通る実装でした。旧HTMLが新バージョンのService Workerキャッシュへ入り、旧HTMLと現行バンドルの不整合を起こす余地があるため、今回確認できた更新処理上の欠陥として修正しました。

## 実装・配信設定の確認

- `index.html`はmanifestとApple touch iconをGitHub Pagesの`/heibon-mahjong/`配下から参照し、iOS standalone用metaを持ちます。
- `public/manifest.webmanifest`の`id`、`start_url`、`scope`はすべて`/heibon-mahjong/`。192／512／maskable 512アイコンとiPhone用180アイコンをビルド時生成します。
- `src/pwa/register.ts`は本番の通常アプリURLでだけWorkerを登録し、同じbase scopeを指定します。開発・検証ページと通常のブラウザー利用は引き続き利用できます。
- Workerは同一オリジンの同一Pagesパスにある静的シェルだけを対象にし、別オリジンのWorker API／WebSocketをキャッシュしません。オフライン範囲はキャッシュ済みシェルからのCPU対局新規開始までです。
- GitHub Pages本番HTTPはネットワーク制限のため直接未確認です。ソース確認やローカルbuildを、本番配信確認と同じ扱いにはしません。

## 今回の修正

- `scripts/build-pwa.mjs`: Service Workerのインストール時に各precache URLを`cache: 'reload'`で取得し、既存HTTP cacheの旧HTMLを新しいシェルへ持ち込まないようにしました。通常ナビゲーションは`cache: 'no-store'`でネットワーク優先取得し、通信失敗時だけバージョン別シェルへfallbackします。
- `tests/pwa.test.mjs`: 事前キャッシュのHTTP cache再検証と、起動HTMLのHTTP cache回避を確認します。
- `tests/browser-pwa.py`: 新規プロファイルからの初回有効化、manifest・MIME・アイコン、スコープ、通常ブラウザー表示、オフラインCPU対局、precache失敗後に旧Workerが動作を維持して配信復旧後に再試行できること、古いHTTP cacheが残る状態での新バージョン検出、別タブによる更新保留、更新承認、旧Cache Storage削除をChromium／Playwright WebKitで検証します。
- オンライン対局・再接続の回帰は既存のBrowser UIモックテストとWorker統合テストで確認します。Service WorkerはWorker API／WebSocketをキャッシュしない設計を維持します。
- Deploy gateやWorker API互換性、ゲームロジックは変更していません。
