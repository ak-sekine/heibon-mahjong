# Issue #31 — PWAインストールと更新管理（2026-11-03）

対象: [Issue #31](https://github.com/ak-sekine/heibon-mahjong/issues/31)

## 実装対象と安全境界

- GitHub Pagesの配信基点は固定の `/heibon-mahjong/`。manifestの`id`・`start_url`・`scope`、Service Worker登録スコープと一致させる。
- manifestは`public/manifest.webmanifest`。iOSホーム画面用180px、通常192/512px、maskable 512pxの透過なしPNGアイコンは`scripts/build-pwa.mjs`が本番ビルド時に`dist/icons/`へ生成する。
- `npm run build`でVite出力を作った後にService Workerを生成。ビルド出力のJS/CSS等のファイルと画面を、ハッシュが変わるバージョン別Cache Storageへ事前保存。取得に失敗した場合はService Workerのインストールを完了させない。
- **通常オンライン時の画面遷移はネットワーク優先**。通信が失敗した場合だけ、同じビルドで保存した起動HTMLを表示する。HTMLは後から旧キャッシュへ書き戻さない。ハッシュ付き静的アセットは事前保存済み内容を利用する。
- **Worker API・WebSocket・別オリジンの通信・検証ページはキャッシュしない**。オンライン対局はオフライン動作を保証しない。オフラインでも起動できる範囲は対局の新規開始とローカルCPU対局（初回オンライン時のService Workerインストール完了が必要）。アプリの画面再読み込み時に未完了の対局状態が復旧することは保証しない。
- 新しいService Workerは自動`skipWaiting`しない。更新を検知すると画面上部に案内を表示し、更新ボタン→確認ダイアログ→`ACTIVATE_UPDATE`メッセージで切り替える。別の同一スコープのウィンドウが開いている場合は切り替えず、閉じるよう案内する。ユーザーが更新を選んだタブのみ制御交代後に再読み込みする。
- 既存のGitHub Pages、Vite base、Worker公開、Deploy gateは維持。Cloudflare WorkerのAPIプロトコルとの互換性保証をService Workerだけで実現できるわけではないため、サーバー側の変更は既存の互換性・Deploy gateに従う。
