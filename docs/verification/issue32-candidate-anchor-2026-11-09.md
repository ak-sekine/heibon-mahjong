# Issue #32 候補パネルの位置・高さ管理共通化 — 2026-11-09

対象: [Issue #32](https://github.com/ak-sekine/heibon-mahjong/issues/32)。IssueはOpenを維持します。[従来の検証履歴](issue32-responsive-layout-2026-11-03.md)は削除・上書きしません。

## 実機報告と原因

ユーザーのiPhone Safari実機報告（修正前）:

- ポン: 候補選択へ切り替えると、パネル全体が上方向へ移動する。
- カン: 元の操作パネルの下端を維持し、候補が増えた分だけ上方向へ伸びる。

旧実装では鳴き種類の`.call-controls`がabsolute配置で、親の高さ計算から外れていました。鳴き中は通常の案内・キーボード説明と通常操作ボタンも消えるため、親rootは余白程度に縮みます。ポン／チーは`chooseCallType()`でそのrootを保存し、実際に見えている種類選択パネルより上にあるroot下端を候補下端に使っていました。暗カン／加カンは`update()`から、通常操作を隠す前の高さを保存していました。同じ採寸メソッドでも、採寸時の内容と実際の高さが異なっていました。

さらに`data-mode="call"`だけに適用する卓サイズ変更がCSSに残り、候補一覧の上限も保存下端の高さを考慮していませんでした。

## 共通設計

- 既存共通HTMLテンプレートは維持。ローカル／オンラインの状態生成、合法判定、CPU、通信仕様は変更しません。
- 鳴き種類も通常フローに置き、その操作領域をrootの実測高さへ含めます。
- `chooseCallType()`は選択種別を設定して共通`update()`へ渡します。全候補は`showCandidates()`だけを通り、通常表示のroot下端（document座標）とborder box高さを非表示前に保存します。
- 保存した高さを共通`.candidate-active`で予約し、通常操作・種類ボタンを隠します。fixed候補パネルを保存下端へ合わせ、増加分を上方向へ伸ばします。
- 一覧の上限は保存下端から可視領域上端までの実際の距離。共通flexレイアウトで一覧だけを内部スクロールさせ、下側の「戻る」を保持します。
- 通常表示時は下端補正・自動ページスクロールを行いません。可視領域が変化した場合だけ、画面内に収める最小限の上下補正を許します。復元時は保存下端へ戻します。
- 戻る・状態終了・clearで位置と高さ予約を解除します。候補送信中の二重実行防止と戻る禁止を維持します。
- `CandidateSelection`の牌画像のみのボタン、下側の「戻る」、単一ポン／チー／大明カン即実行、暗カン／加カン候補確定は維持します。
