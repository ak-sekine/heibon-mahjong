# Step 13.5.4 — 卓上牌の拡大

基準コミット: `36e9dc6abb499c35e56465f92d78df67f211454c`。fetchでorigin/mainと一致することを確認して開始しました。製品の変更は `src/style.css` のみです。麻雀ルール・得点計算・CPU戦略・非公開牌のDOM描画は変更していません。

## 結果と評価範囲

指定された**14枚時の手牌サイズ**を維持し、通常ページと `kan-test.html` の全7画面サイズで、ドラ・CPU裏面・河・副露の幅を手牌の100%にしました。高さによる縮小は廃止しました。横向き牌・加カン・暗カン・槍槓プレビューにも同じ寸法を使います。

一方、既存の「副露後に少数の手牌が自動的に最大42pxへ拡大する」挙動も維持しています。**この自動拡大後の手牌に対する85%以上は、スマートフォンでは未達です。** 全局面で100%という意味ではありません。詳細と実測値は後述します。手牌を縮小して比率を合わせる変更は行っていません。

## レイアウト

- 共通幅は `--table-tile-width: min(42px, round(down, (100cqw - 21px) / 14, 1px))`、高さはその1.4倍。21pxは卓の左右border/padding計8pxと手牌の13個の1px gapです。従来の14枚手牌の実寸に一致します。卓上牌の18px上限・低い画面の14px上限を廃止しました。
- 960px未満では左右席を「情報→裏向き手牌→副露」の縦並びにします。中央情報は上河と左右河の間の独立行へ移動し、ドラ5枚を1行に配置します。左右の河は90/270度、上河は180度の向きを維持します。
- 960px以上はmainの最大幅を620→1000pxへ拡張。左右席の手牌と副露を横に分け、中央情報を左右河の間へ戻します。手牌領域は最大604px、各牌は従来と同じ最大42pxです。
- 全河は6枚×3段（左右は回転後の3列×6行）を維持。各セルは横向きリーチ牌の占有寸法も確保する正方形です。河の予約領域は空でも18枚でも同じため、捨て牌追加で操作欄を押し下げません。
- CPU1/3のラベルは牌とは独立した領域に対称配置。名前・風・点数・リーチ・手番・加カン宣言を維持します。副露最大4面子の行高と加カンの重ね余白も共通牌幅から計算します。
- 卓と操作欄は通常の文書フローです。1画面に収めるための縮小や固定オーバーレイを使わず、縦スクロールで操作します。既存のセーフエリア・visualViewport補正を維持します。

### 少数手牌時の制約

手牌描画は従来どおり残り枚数分の列を作り、空いた横幅で手牌を拡大します。5枚手牌の描画fixtureでは、両ページ・全幅で手牌とツモ牌が42×58.7969pxになりました。卓上牌は上表の幅を維持するため、比率は次のとおりです。

| 画面幅 | 卓上牌/自動拡大後42px手牌 |
| --- | --- |
| 320 | 47.62% |
| 375 | 57.14% |
| 390 | 59.52% |
| 414 | 64.29% |
| 430 | 66.67% |
| 1280 | 100% |

この条件は85%下限を満たしていません。CPU2の13枚を1列で配置する場合、42px牌はgap込み558pxを必要とし、320px画面の卓内容幅304pxには収まりません。85%の35.7pxでも476.1px必要です。今回は手牌縮小を避け、依頼に記載された14枚時の寸法を卓上牌の固定基準にしています。少数手牌時も同じ比率にするには、CPU手牌の折り返し等を含む追加の配置変更が必要です。
